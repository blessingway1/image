# 원문 대조 — 네트워크 준비와 대조 절차

조사 리포트·대본의 🔍 항목을 [원문확인]으로 올리는 단계다. 대본 3단계가 끝난 뒤(녹음 전) 반드시 돌린다.

## 1. 먼저 네트워크가 열려 있는지 확인한다

클라우드 세션의 기본 네트워크 정책은 학술 사이트를 막는 경우가 많다(2026-10-12 실측: 설정 전 pubmed·doi.org·KCI·RISS 등 전부 차단).

확인 명령(한 번에):
```
for u in https://pubmed.ncbi.nlm.nih.gov/ https://pmc.ncbi.nlm.nih.gov/ https://journals.plos.org/plosone/ https://www.merckvetmanual.com/; do printf "%s " $u; curl -s -o /dev/null -w "%{http_code}\n" -L --max-time 20 "$u"; done
```
200이 아니면 사용자에게 아래를 안내하고, 그동안 원문이 필요 없는 작업을 계속한다. 열리지 않은 상태에서 결과를 지어내지 않는다.

### 사용자 안내 (PC 웹 claude.ai/code 기준, 2026-10-12 사용자 화면으로 확인)
1. 세션 제목 옆 **「환경 이름 · 저장소」 칩**(예: 「기본 · image」)을 누른다 → 「클라우드 환경」 창.
2. 환경 이름 줄의 **편집(연필/톱니)** → **Network access**.
3. **Limited** 단계의 **Allowed domains**에 아래를 한 줄씩 추가(「Allow package managers」 체크는 유지). 앱이 구버전이면 **Custom** 아래에 있다.
4. 공식 안내: https://code.claude.com/docs/en/cloud-environments#network-access
5. 현재 세션에 바로 적용되지 않으면 같은 환경으로 새 세션을 연다.

허용 권장 도메인:
```
pubmed.ncbi.nlm.nih.gov
pmc.ncbi.nlm.nih.gov
www.ncbi.nlm.nih.gov
doi.org
peerj.com
journals.plos.org
www.merckvetmanual.com
link.springer.com
www.sciencedirect.com
onlinelibrary.wiley.com
www.cell.com
```

### 허용 후에도 막히는 곳 (실측)
| 사이트 | 증상 | 우회 |
|---|---|---|
| peerj.com | curl 403 | 같은 논문의 **PMC 사본**(PeerJ는 대부분 PMC에 있음) |
| sciencedirect.com · 일부 대학 저장소 | 차단 | PubMed 초록 + 검색 결과의 원문 발췌. 등급은 [초록확인]까지만 |
| doi.org | 리디렉션 대상이 막히면 404·403 | 저널 사이트 도메인도 함께 허용, 또는 PMC로 |

**PMC 전문이 가장 확실한 경로다.** 먼저 PMC에서 찾고, 없을 때만 저널 사이트로 간다.

## 2. 대조 절차

1. 대본에서 🔍 문장을 모두 뽑아 **번호 목록**으로 만든다(문장 원문 + 기대하는 근거 논문).
2. 항목이 6개를 넘으면 **서브에이전트 2개로 나눠 병렬** 실행한다. 각 에이전트에게 fact-check-rules.md를 먼저 읽히고, 항목마다 아래를 요구한다.
   - 원문 서지(저자·연도·저널·권호·DOI·URL), 기관·국가
   - 표본·방법·**측정 방식**
   - **원문 인용**(영어 그대로 1~3문장) — 근거로 쓴 문장을 남겨야 다음에 재검증할 수 있다
   - 판정: 확인됨 / 부분 정확 / 출처 오류 / 결과 반대 / 미확인
   - **교체용 낭독 문장**(확인됨이 아니면 필수, 25자 내외 문장 단위)
   - 자막 한계 문구(나레이션 금지 내용은 여기로)
   - 자막에 써도 되는 수치(원문에서 확인된 것만)
3. 결과를 받아 대본을 고치고, 고친 문장 옆 표시를 🔍 → (확인 출처 약칭)으로 바꾼다.
4. 대조 결과 파일은 레포 `research/<날짜>_<소재>/factcheck_*.md`에 남긴다.

## 3. 대조에서 실제로 잡힌 오류 유형 (2026-10-12 소파 편)

| 유형 | 사례 | 교훈 |
|---|---|---|
| **개념을 바꿔 옮김** | Kubinyi 2019는 보호자가 본 「대장(dominant)」을 쟀는데, 대본은 「누가 먼저 물러서는지」로 옮김 | 금지 프레임을 피하려고 바꿔 쓴 말이 원 연구에 없는 개념이 되면 안 된다. 원 연구의 **실제 문항**(예: 「누가 더 좋은 쉼 자리를 차지하나」)으로 다시 쓴다 |
| **가장 강한 요인으로 과장** | 「몸집보다 나이」 — 나이는 관련 있었지만 가장 강한 요인은 아니었음(후속 연구에서 성격 요인이 더 큼) | 「A보다 B」 비교 문장은 B가 1위인지까지 확인한다 |
| **설계를 장면으로 각색** | Mariti 2017은 처음 만난 두 마리를 5분간 함께 둔 영상 분석 파일럿인데, 대본은 「부딪히는 순간을 관찰」 | 실험 설계를 장면 말로 옮길 때 조건이 바뀌지 않게 한다 |
| **조건을 넓혀 말함** | Gácsi 2013 — 위협 장면 동안 「조용히 앉아 있기」였지 처음부터 쓰다듬기 금지는 아님 | 「~하지 않아도」 같은 조건절은 원문 조건과 일치해야 한다 |
| **존재 → 빈도 비약** | 「설문에 문항이 있을 만큼 흔한 장면」 | 문항이 있다는 것은 흔하다는 증거가 아니다 |
